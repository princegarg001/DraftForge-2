How it works
Security model

Deterministic scoring

Grading runs no model inference. The same draft scores identically on every run, and every point is attributable to a named rubric criterion with cited evidence.

Evidence you can follow

Findings carry the source document, section and page they came from — hybrid vector plus lexical retrieval over an indexed corpus of Indian statutory precedent.

Prerequisite-aware analysis

A knowledge graph traverses clause dependencies, so an arbitration clause with no governing-law clause is flagged as an enforceability gap rather than passing in isolation.

Socratic, not substitutive

The AI tutor asks statutory questions instead of rewriting the draft. Students keep the cognitive work that the learning depends on.

Roster-based onboarding

Instructors build a class and invite students by email. Nobody self-selects a role, and coursework, analytics and leaderboards are scoped to the class.

Traced end to end

OpenTelemetry spans cover embedding, retrieval, graph traversal, inference and scoring — with token-level cost attribution on every LLM call.

The core claim ​

Most LegalTech tools ask a language model to grade a document. That produces a score that changes between runs, cannot be justified to a student who disputes it, and is capable of confidently citing a statute that does not exist.

DraftForge splits the problem in two:

The generative layer never writes to a score. That separation is what makes the mark defensible: a student disputing a result is shown the criterion, the evidence and the rule that produced it.
